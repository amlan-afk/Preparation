## 🎯 The SDE 2 Verbal Walkthrough Protocol

In SDE 2 interviews, solving the problem is only 50% of the grade; the other 50% is how you communicate, validate assumptions, and reason about trade-offs:

```
[00:00 - 03:00] Step 1: Clarify & Bound
   └─ Ask constraints (N size, element ranges, negative numbers, duplicates).
   └─ State assumptions aloud and confirm with the interviewer.

[03:00 - 07:00] Step 2: Brute Force -> Optimal Invariant
   └─ State naive O(N^2) solution in 30 seconds.
   └─ Identify the bottleneck (e.g. repeated lookups -> Hash Map; sorting -> Two Pointers).
   └─ Formulate the invariant: "At every index i, we maintain..."

[07:00 - 10:00] Step 3: Dry-Run the Strategy on a Sample Case
   └─ Trace the logic on a small example (4-5 elements) BEFORE writing code.
   └─ Check edge cases (empty input, 1 element, all identical, extreme values).

[10:00 - 25:00] Step 4: Write Clean, Modular Code
   └─ Meaningful variable names (not just x, y, a, b).
   └─ Handle edge condition guard clauses at the top of the function.
   └─ Narrate your actions as you type.

[25:00 - 30:00] Step 5: Self-Testing & Complexity Defense
   └─ Manually step through the code with pointer updates on the whiteboard/editor.
   └─ State exact Time Complexity and Space Complexity with clear justification.
```
